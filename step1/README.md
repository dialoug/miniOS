# 阶段 1：C/C++ 与开发工具基础

> 建议时长：4–6 周（已有较熟练 C++ 基础的压缩安排）  
> 阶段目标：以 C 的思维编写、调试和分析程序；理解 C 程序如何被编译、链接和执行，为 Linux 用户态与内核源码阅读奠定基础。

## 为什么还要系统学习 C

Linux Kernel 主要使用 C 和少量汇编。你已有 C++ 基础后，不需要重复学习算法或面向对象设计；应集中补足 C 的显式资源管理、内存布局、编译链接、错误处理和并发基础。

尤其要适应内核常见的代码组织方式：**结构体 + 函数指针回调 + 宏 + 错误码**，而不是 C++ 中的类、RAII、异常和 STL。

## 本阶段学习结果

完成后应能：

- 独立用 C 完成包含动态内存、错误处理和回调的中小型程序。
- 解释数组/指针、栈/堆/静态区、结构体对齐、生命周期和常见未定义行为。
- 使用 `gcc`/`clang`、Makefile、GDB、sanitizer、`readelf`、`objdump` 分析程序。
- 读懂基础 pthread 并发代码，识别数据竞争与资源泄漏。
- 理解并能初步使用 Linux 内核常见惯用法：侵入式链表、`container_of`、错误指针和回调。

## 推荐工作方法

1. 每个概念都写一个不超过 100 行的最小验证程序。
2. 每个程序至少用一次 GDB 和 sanitizer 观察行为。
3. 记录“现象、原因、验证命令、结论”，不要只保存最终代码。
4. 优先理解资源所有权和失败路径；这是 C/内核代码中最易出错也最重要的部分。

## 阶段验收

在进入 `step2` 前，请能够不查资料完成或解释：

- 动态数组如何扩容、释放及处理失败。
- `char *`、`char []`、`const char *` 的差异和风险。
- 为什么结构体大小不等于字段大小之和。
- C 程序从源文件到可执行文件的编译、链接和加载过程。
- 如何用 GDB 和 AddressSanitizer 定位越界或 use-after-free。
- 为什么条件变量要配合循环检查条件，且持有自旋锁时不能睡眠。
